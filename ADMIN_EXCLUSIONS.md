# PaperWorking SaaS Admin Panel — Explicit Exclusions & Architectural Guardrails

The following table documents features that are **EXPLICITLY NOT TO BE BUILT** in any prompt of the PaperWorking SaaS Admin Panel pack, along with research rationales and replacement strategies.

| Not Building | Why (Research Rationale) | What to Do Instead |
| :--- | :--- | :--- |
| **Impersonation / "view as user"** | Highest-risk admin capability; Twitter-2020 and Retool-2023 breach patterns; converged defer decision across dim04/dim06/dim10/dim12 (Conflict C4). | Alternatives-first (dim04): masked session replay, co-browse with live customer consent, or **read-only backend-rendered shadow views** with sensitive widgets hidden (built only if genuinely needed, after audit substrate matures). Revisit only with dual-identity tokens, ≤60-min read-only sessions, mandatory reason + ticket link, persistent banner, real-time alerts, hidden Plaid/billing widgets. |
| **SLA timers / countdowns / breach escalation** | Conflict C1 resolution: Help Scout small-team model validated; SLA engines are the deepest config rabbit hole (dim01). Add at first enterprise contract (dim09). | Ship `priority` field (`Low`/`Normal`/`High`/`Urgent`) in data model now so SLAs layer on later without migration. Optional informal internal response targets only. |
| **AI support / chatbot / autonomous anything** | ~70% first-year failure when layered on an unaudited KB; vendor-reported resolution rates are inflated; per-resolution pricing punishes scale (dim11; cross-verification medium-confidence). Human handoff demanded by 89% of customers. | Human-run inbox with saved replies. Revisit AI drafting only after a KB exists and passes audit; autonomous AI later still. |
| **⌘K command palette inside /admin** | Conflict C2 resolution: global search first; palette is a power-user fast-follow (dim02). | Fast field-scoped search box with grouped typed results. (The existing user-facing shell's ⌘K, if any, stays untouched.) |
| **Health scores, churn risk, LTV/RFM analytics** | Stripe itself doesn't compute these on the customer page; belongs to analytics tooling later (dim02). | Show raw billing state and real activity only. |
| **Deep Stripe clone** (disputes, payouts, product/price authoring, tax, rev-rec, dunning schedule config) | Duplicates vendor risk surface; 10 defer-to-Dashboard items vs 9 build items (dim07). Insight 3: build the context, delegate the transaction. | Read-federated status blocks + deep links to Stripe Dashboard + at most 2–3 guarded write actions. |
| **Auto-assignment routing (round robin/balanced), custom statuses, merge, bulk ticket ops** | Small-team boundary: manual/claim assignment and 3 states suffice; automation accrues edge cases faster than value at this volume (dim01). | Mine/Unassigned/All tabs + claim. |
| **Self-hosted status page** | Must survive the outage it reports on; never host on own infra (dim09/dim11). | Third-party hosted status page later; Plaid institution-health surface in Prompt 5 covers the bank-side slice. |
| **Low-code/vendor admin platform (Retool etc.)** | Non-exportable proprietary config, closed source, 2023 breach blast radius was exactly "admin modifies customer data" (dim12). | Build in-app as `/admin` with owned React/TypeScript code. |
